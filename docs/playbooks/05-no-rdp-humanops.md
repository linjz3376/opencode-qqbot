## 0. 一句话架构

**命令下行走 WinRM，操作执行在远端本机（交互会话里的计划任务），画面回传走 HTTP POST 或文件拉回。**

```
控制端                                    执行端
───────                                  ───────
pywinrm/Invoke-Command ──推送脚本──▶ 计划任务(Interactive) ── pyautogui 点击/输入
                                        └─ 屏幕 BitBlt 截图(GPU 窗可抓)
        ◀──── HTTP POST 图片 / Copy-Item 拉回 ────  :<回传端口>
```

为什么不是 RDP：RDP 需要控制端屏幕可见 + 合成输入不被安全桌面拦；WinRM 是纯网络通道，
控制端锁屏/关 RDP 全不影响。执行端的桌面由它自己的控制台会话渲染，与控制端无关。
（用例：RDP 客户端被杀掉后链路不受影响，抓图照常成功。）

## 1. 前置条件（开工闸，缺一即停）

| # | 条件 | 检查方式 | 失败处置 |
|---|---|---|---|
| 1 | 执行端 WinRM 可达且凭据有效（组件①远程执行器） | 用例：执行 `whoami` → 回显执行端账户 | 查 5985 端口 / LocalAccountTokenFilterPolicy |
| 2 | 执行端有**活动控制台会话**（非 Disc） | 用例：执行 `qwinsta` → `console ... Active` | 若有 RDP 会话：`tscon <id> /dest:console` |
| 3 | 执行端不锁屏 | `powercfg /change monitor-timeout-ac 0` 已设；会话状态 Active | 重新下发 powercfg；**锁屏的会话无法拟人操作**（安全桌面拦合成输入） |
| 4 | 目标客户端已登录（自动登录勾选） | 截图看主面板 | 需人工扫码一次（唯一人工点） |
| 5 | 回传口存活（组件③接收端） | `curl http://<控制端IP>:<回传端口>/` → PONG | 启动接收端（功能契约见 §6） |
| 6 | 执行端装有 Python + pyautogui/pyperclip | 用例：执行 `<python绝对路径> -c 'import pyautogui'` | pip 装（镜像源） |

## 2. 核心循环（拟人操作四拍）

**观察 → 判定 → 动作 → 复核**，一拍不少。禁止盲点。

```
① 观察：抓当前帧（屏幕 BitBlt）→ 回传控制端 → 人/agent 看图
② 判定：确认目标控件在帧内的坐标（相对窗口左上角）
③ 动作：click / type / key / wait（执行端本机 pyautogui 真实事件）
④ 复核：再抓一帧，断言可观察变化（标题变/列表变/消息上屏/角标变）
```

- **动作后无变化 = 该次操作不算完成**：重试一次（幂等前提），仍无变化记「操作无响应」并转缺陷候选。
- **每步截图都回传**，既是复核也是验收证据（按 `AC-ID_步骤_时间戳` 命名归档）。

## 3. 动作 DSL

驱动器（组件②，功能契约见 §6）内置「恢复窗口→固定槽位→TOPMOST 置顶→逐动作执行→截图回传」。
通用动作集：

| op | 参数 | 说明 |
|---|---|---|
| `click` | `x, y` | 窗口相对坐标（槽位原点 + x,y），真实鼠标点击 |
| `type` | `text` | **剪贴板粘贴**（pyperclip + Ctrl+V）——中文/emoji 安全，不用 typewrite |
| `key` | `key` | 单键（`enter`/`esc`/`tab`/`pageup`…） |
| `wait` | `ms` | 等待（渲染/网络/动画） |
| `shot` | — | 抓帧并回传（自动编号） |

用例（已验证：搜索开会话 + 发消息）：

```python
ACTIONS = [
    {"op": "click", "x": 100, "y": 163},   # 目标会话（坐标从当前帧实测）
    {"op": "wait", "ms": 1200},
    {"op": "shot"},
    {"op": "click", "x": 600, "y": 700},   # 输入框
    {"op": "type", "text": "冒烟消息"},
    {"op": "key", "key": "enter"},
    {"op": "wait", "ms": 3000},
    {"op": "shot"},
]
```

## 4. 硬纪律（全部有失效实证）

1. **坐标永远来自当前帧**——会话列表按未读重排、搜索框弹层会位移；上一帧的坐标下一帧就可能点错
   （实证：点目标 A 落到相邻 B，还误触搜索弹窗）。
2. **会话/条目寻址优先用搜索**——搜索框位置固定，结果列表比主列表稳定；
   注意结果里的「搜索全部」类行会开弹窗，要点**目标条目行**（带来源副标题那条）。
3. **窗口先恢复再操作**——最小化的窗不在可见枚举内（`IsIconic`），必须 `ShowWindow(SW_RESTORE)`。
4. **置顶用 HWND_TOPMOST + 固定槽位**——远端其它窗口（终端等）会抢焦点；
   TOPMOST 让目标窗口常驻最上层，槽位固定让坐标可复用（用例槽位 `(350,100,1230,870)`）。
5. **文字输入只走剪贴板**——`pyperclip.copy + Ctrl+V`；`typewrite` 对中文/长文本不可靠。
6. **选窗过滤隐藏窗**——只认 `IsWindowVisible`；否则会「把隐藏窗挪到槽位」得到黑图
   （实证：黑屏多次，全是选了不可见窗）。
7. **两路验证**——UI 截图（用户可见证据）+ 被测系统侧日志（功能证据）。UI 点 PASS 必须有截图；
   功能是否真送达以系统侧日志为准，两者不可互相替代。

## 5. 截图技术选型（血泪结论）

| 方法 | GPU 加速窗（Electron/Chromium 类） | 说明 |
|---|---|---|
| **屏幕 BitBlt（GetDC(0) + 区域拷贝）** | ✅ **可用** | DWM 重定向后能抓到 GPU 窗内容；本 Playbook 默认 |
| PrintWindow(flag 0/2) | ❌ 全黑 | GPU 表面不响应 WM_PRINT（实测中心区亮度 0.0） |
| 窗口自身 BitBlt | ❌ 黑 | 同上 |
| UIA 控件树 | ❌ 空树/裸树 | Chromium 客户端未开 a11y 时只有外壳节点 |
| DXGI ddagrab（ffmpeg） | 备选 | 需装 ffmpeg；屏幕 BitBlt 已够用，不引入 |
| RDP 画面 | 已退役 | 控制端锁屏即废，不再作为主通道 |

**亮度自检**：抓完算中心区均值（避开标题栏）。`mean < 5` = 黑图/抓错窗，直接判失败重抓。

## 6. 远端执行通道

- **推送**：脚本 base64 **分块**（每块约 1000 字符，4 字符对齐）→ 逐块追加写远端文件。
  单次命令有约 8191 字符上限，3KB payload 就会「The command line is too long」（实证）。
  替代：走 PSSession 的 `Copy-Item -ToSession` 直接传文件，免分块。
- **执行**：注册 `LogonType Interactive` 计划任务 → 启动 → 等 N 秒 → 注销任务。
  **必须 Interactive**：session 0 起的 GUI 进程看不到桌面；**必须非提权**（提权起的 Electron 会挂死，实证）。
- **回读**：结果写远端 UTF-8 文件（用例：`C:\Users\Public\uat-qr\task.out.txt`），WinRM 读回（防乱码）。
- **图片回传**：执行端 POST 到控制端接收端（用例：端口 10247，`X-Filename` 头带文件名）。
  该端口可复用已有防火墙放行规则；控制端也可改用 `Copy-Item -FromSession` 拉回，免常驻接收端。

### 组件功能契约（三个组件按此描述即可自动重建，无需任何现成代码）

**① 远程执行器（控制端）**
- 职责：接收一条命令字符串，经 WinRM(NTLM) 在目标机 Session 0 执行并回传 stdout/stderr/退出码。
- 输入：待执行命令（任意长度，内部分块规避约 8191 字符命令行上限）；目标机地址与凭据（密钥源注入，不回显）。
- 输出：执行端控制台文本输出 + 退出码；非零退出码视为失败。
- 重建要点：pywinrm 或直接 `Invoke-Command`；长于上限的 payload 按约 1000 字符 base64 分块传输（见 §6 推送）。

**② 拟人驱动器（执行端，跑在交互会话内）**
- 职责：按动作表对目标客户端窗口执行真实用户等价操作，逐步回传截图。
- 输入：动作 JSON 表（§3 五操作）；目标窗口标题/进程名关键字；槽位坐标 `(x,y,w,h)`。
- 行为序：枚举窗口并过滤可见（`IsWindowVisible`）→ 匹配目标窗 → 若最小化则恢复（`SW_RESTORE`）→
  移动到槽位并 `HWND_TOPMOST` 置顶 → 逐条执行动作（click=真实鼠标；type=剪贴板粘贴+Ctrl+V；key=单键；
  wait=睡眠；shot=抓帧）→ 每帧经回传通道发控制端。
- 输出：逐帧图片（自动编号）+ 执行日志（动作序号/坐标/结果）。
- 重建要点：pyautogui + pyperclip + win32gui（窗口枚举/置顶/恢复）；截图用屏幕 BitBlt（§5 选型）。

**③ 回传接收端（控制端，常驻进程）**
- 职责：接收执行端 POST 的图片帧并落盘。
- 接口：`GET /` → 返回 `PONG`（健康检查）；`POST /upload`，请求体=图片字节，`X-Filename` 头=文件名 →
  存 `<工作目录>/shots/` 并返回 200。
- 重建要点：任意微型 HTTP 服务（Python http.server 子类/Node/…）；监听 `<回传端口>`。

## 7. 常用玩法（Recipe）

### R1 开会话并确认标题
搜索框 → 输入目标名 → 等结果 → 点目标条目 → 抓帧。
判据：标题栏出现目标名。

### R2 发消息并等回执
点输入框 → 粘贴消息 → enter → 等待 → 抓帧。
判据：消息气泡上屏（右对齐）+ 被测系统侧日志出现收件与回复。

### R3 点卡片按钮
1. 先抓帧，**人工读图**定位按钮（卡片按钮位置随内容高度变化，不可复用旧坐标）；
2. 单点 + 等待 + 抓帧，确认卡片状态变（按钮置灰/文案变「已处理」）；
3. 点击无变化：等 500ms 重试一次（可能在动画中），仍无变化记「操作无响应」。

### R4 滚动消息区
点消息区中部 → `pageup`/`pagedown`（多数客户端支持），或鼠标滚轮（需扩展 DSL）。

### R5 发图片/文件（媒体点）
1. 先把文件放到执行端可达路径（WinRM 分块推送或文件传输）；
2. 点输入栏「图片」按钮（坐标实测）→ 系统文件对话框 → 地址栏输入路径（`type` + `enter`）；
3. 抓帧确认媒体进入输入框 → `enter` 发送 → 抓帧确认媒体气泡。

### R6 长等待/异步（长窗类）
`wait` 分段 + 多次 `shot`；控制端轮询读取回传图片。**不要**在单次任务里 sleep 过长
（计划任务/超时不可靠），改为多次短任务轮询。

## 8. 失败模式与处置（速查）

| 症状 | 根因 | 处置 |
|---|---|---|
| 抓图全黑 | 抓错窗（隐藏窗）/ 窗口被覆盖 / GPU 表面 | 过滤可见窗 + TOPMOST + 中心亮度自检 |
| 点击无反应 | 坐标过期（列表重排/弹层） | 重抓当前帧重取坐标；改用搜索寻址 |
| 输入中文变问号/乱码 | typewrite 编码问题 | 只走剪贴板粘贴 |
| 任务执行但无输出 | 计划任务非 Interactive / session 0 | 检查 LogonType=Interactive；确认 console 会话 Active |
| 脚本推送失败「命令行过长」 | 单次 payload 超限 | 分块推送；或 `Copy-Item -ToSession` 传文件 |
| 远端 Python 找不到 | PATH 未继承 | 一律用绝对路径调用解释器 |
| 误触「综合搜索」类弹窗 | 点到了结果里的聚合行 | Esc 关闭；点目标条目行（带来源副标题） |
| 执行端锁屏后全部失效 | 安全桌面拦合成输入 | 保持不锁屏；锁了只能人工解锁（唯一例外） |

## 10. 边界声明

- ✅ 执行端控制台会话 + 客户端登录态下：开窗/置顶/搜索/点会话/发中文消息/截图回传，全链路可用；
- ✅ 控制端锁屏或 RDP 断开，链路不受影响；
- ⚠ 未验证：执行端自身锁屏后（安全桌面）——按设计不可操作，需保持不锁屏；
- ⚠ 未验证：UIA/控件级语义操作——Chromium 类客户端未开 a11y 时走坐标+视觉判定；
- ⚠ 分辨率/显示模式会变（虚拟显示器尤其如此，WMI 报值可能漂移）——**槽位坐标用前以当前帧重实测**。
