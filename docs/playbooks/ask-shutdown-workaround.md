# ask 通道隐式放行·规避规程（WO-20261113-3）

> 背景：DEF-P1（ask-shutdown）——PM-105「总是允许」把放行**落盘持久化到项目级权限存储**，
> 引擎重启后照读，ask 通道整体关闭（2026-11-19 实弹定性：非内存缓存，config 全文核验无新增）。
> 六点审批族（PM-102/103/104/RE-002/PM-107）解除条件被堵。本规程=不等上游的 bot 侧规避：
> 探针链前置「权限存储快照 → 清理 → 回放 → 还原」，全程可逆、先干后记合规。

## 适用

- 任何依赖 `permission.asked` 必然触发的验收/回归（审批卡族、PM-TTL、RE 族）
- 前置确认：引擎版本仍在「saved 落盘即隐式放行」行为期（修复前）；修复后本规程降级为回归用例

## 规程（四步）

1、**发现（不写死端点）**：引擎 OpenAPI 先行——`GET /openapi.json`（或 `opencode api get /openapi.json`）
   定位 permission 存储的读/写端点与请求体 schema；本机快照存档发现的 schema 版本。

2、**快照**：探针链开始前，读出当前项目级权限存储全量 → 落盘
   `<报告树>/obs/permission-saved-snapshot-<yyyyMMddTHHmm>.json`（含时间戳与引擎版本）。
   快照是还原的**唯一基准**，缺失即不得进入下一步。

3、**清理**：删除/清空项目级权限存储中由测试产生的放行条目（按快照逐项核对，只删测试条目；
   对存储无条目级删除端点的形态——整表快照+整表清空+按快照还原）。

4、**回放**：原样执行已备好的探针链（PM-102 语料八连等），收判要求不变——
   asked 事件必须重新出现；若某探针仍零 asked，按「隐式放行未清除」重新走 2-3，禁止改判据凑合。

5、**还原**：链收尾后按快照逐项写回（顺序无关，终态一致为准）；还原后复读存储与快照逐字节对账，
   对账差异=缺陷候选（还原本身也是观测面）。

## 红线

- 快照先于一切写操作；无快照不动存储（secrets 纪律同级）
- 只碰**项目级权限存储**；全局配置（opencode.jsonc）与 .env 只读
- 全程登记 execution-log（动作/通道/对象/还原对账结果）——登记铁律适用
- 本规程不修复 DEF-P1 本身；上游修复落地后，本规程转为例行回归脚本锚点
