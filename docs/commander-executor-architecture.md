# 指挥官/执行者双会话执行架构

长任务验收/执行的标准形态：两个会话、互斥绑定、自主推进、全程可观察。

## 一、角色与资产

| 角色 | 会话 | 职责 | 生命周期 |
|---|---|---|---|
| 指挥官 C | 指挥会话（绑定 persona 面） | 持任务书、派单、观察、判定、取证、终报 | 长回合，从任务启动到终报不主动停止 |
| 执行者 E | 执行会话（不绑 persona 面） | 执行具体任务轮次，产出结果 | 单一长期存活，轮次 E1..En 顺序推进 |

铁律：会话资产全程两个，不增殖；E 的上下文随轮次累积（多步旅程连贯性来源），必要时重置上下文但绑定不变。

## 二、persona 面单活绑定

- persona 面（聊天窗）任意时刻只绑定一个会话：C 或 E，互斥。
- 交权/收权走显式切换命令；切换后首动作前必须完成身份寻址复验（目标标识在取证中可见）。
- 发起人随时可用切换命令抢回绑定（最高优先），抢回即召回指挥官。

## 三、五阶段流程

```text
阶段0 · 初始化
  persona 面绑定 C；C 内创建 E（一次，终身复用）

阶段1 · 交权
  C 发出切换命令 → 解绑 C、绑定 E → persona 面呈现 E 的对话流

阶段2 · 执行期（persona 面 = E 的轮次流）
  loop 直到 E1..En 全部终态：
  ├─ Ei 开始：C 经拟人执行端点输入测试消息 → persona 面 → 被测系统 → E 回合执行
  ├─ Ei 产出回 persona 面（发起人实时可见）
  ├─ Ei 完成 → E 内进入 E(i+1)
  ├─ C 观察回路（静默·零 persona 面噪音）：机器读数读 E 全量轮次
  │   逐轮判定通过/失败 + 取证 + 记台账
  ├─ 发起人插话 → 落入 E = 新轮次（等价测试输入/干预）
  └─ 发起人切换命令 → 随时召回 C

阶段3 · 收权
  C 确认 E1..En 全部终态 → 切换命令解绑 E、绑定 C

阶段4 · 终报
  C 独占 persona 面输出：总账/覆盖度量/缺陷/残余风险
  C 长回合收尾 = 全程唯一停止点
```

## 四、三通道纪律

- 指挥通道：发起人↔C，低噪音（仅里程碑/异常/待裁决时发声）
- 测试通道：E↔被测系统，经拟人执行端点交互，测试面纯净
- 观察通道：C↔E，纯机器读数（接口/日志/台账/取证），不过 persona 面

## 五、指挥官长回合守则

- 不停止：回合持续有动作即不衰减；唯一合法收尾=终报完成。
- 上下文防腐：观察回路低频化（分钟级），每轮只取增量摘要；重活全在 E，C 只做调度与判定。
- 待命纪律：无任务时不自发空转——待命=安静等待发起人消息，禁止巡逻式自唤醒（每次注入都是一次完整模型调用，叠加宿主负载）。
- 断点纪律：每个阶段切换与每批轮次完成时，将进度对账与下一步写入持久断点；长窗收判项用一次性时钟排程，不用常驻任务。

## 六、异常分支

| 异常 | 处置 |
|---|---|
| E 某轮次挂起无进展 | 观察回路的停滞检测：超过阈值判失→销账→通知发起人→按断点重派或跳过 |
| E 上下文膨胀 | C 重置 E 上下文（绑定不变），断点文件带上下文摘要 |
| 绑定漂移（他端切换/选择错位） | 阶段切换前逐条对账目标标识；漂移后先复验再输入 |
| 发起人想干预执行 | 插话落入 E；想改派/终止→切换命令召回 C |
| C 自身回合被异常打断 | 断点文件+持久台账支撑恢复；恢复后从断点继续，不从头重跑 |

## 七、准入条件

- 拟人执行端点已过准入清单（五操作可用）
- 被测系统的会话绑定支持显式切换命令
- 机器读数通道可用（C 观察 E 的接口/日志/台账可达）
- 任务书已将全任务分解为 E1..En 轮次清单（C 持书派单）
