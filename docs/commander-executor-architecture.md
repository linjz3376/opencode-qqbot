# 指挥官/执行者双会话执行架构

长任务验收/执行的标准形态：角色（指挥官 C / 执行者 E）经会话载体体现、persona 面互斥绑定、自主推进、全程可观察。

## 一、角色与资产

C、E 都是角色，由会话载体体现。三层分离：

- 角色：职责与纪律（无状态定义）。
- 载体：会话实例，持有上下文、权限缓存、回合状态——角色的一切状态住在载体里。
- 绑定：persona 面（聊天窗）→ 载体的指针，任意时刻只指向一个（C 或当前任务会话），互斥切换；切换只改「谁经 persona 面说话」，不改角色定义。

载体生命周期策略——C/E 的唯一实质差异，由「上下文是资产还是负债」推导：

| 角色 | 职责 | 载体策略 |
|---|---|---|
| 指挥官 C | 持任务书、派单、观察、判定、取证、终报 | 长命：上下文=资产（任务书/判定史/证据链跨任务累积）；默认单一载体跑到终报，断点文件=换载体续跑协议 |
| 执行者 E | 执行具体任务轮次，产出结果 | 短命：上下文=负债（权限缓存饱和/跨用例污染/僵尸半径）；按任务经机器接口新建专属会话，用完即弃 |

E 的会话取用细则：

- 默认：每个任务（或任务组）新建专属会话——出厂权限态、零上下文污染、僵尸回合只影响本任务。
- 复用历史会话：仅当任务本身验证连续性（多轮旅程连贯、历史记录特性、会话管理特性）——此时上下文转为资产，与 C 同策略。
- 一个任务内的多轮交互留在该任务会话内（旅程连贯性来源）；任务完成即弃，归属清场。

## 二、persona 面单活绑定

- persona 面（聊天窗）任意时刻只绑定一个会话：C 或当前任务会话，互斥。
- 交权/收权走显式切换命令；切换后首动作前必须完成身份寻址复验（目标标识在取证中可见）。
- 发起人随时可用切换命令抢回绑定（最高优先），抢回即召回指挥官。

## 三、五阶段流程

```text
阶段0 · 初始化
  persona 面绑定 C；C 持任务书待命（E 是角色无实体，待任务领取）

阶段1 · 交权（每个任务一次）
  C 从任务书取任务 → 经机器接口新建专属任务会话
  （任务领取走队列文件+认领锁，非人肉派单——WO-20261113-2）
  （例外：测连续性的任务复用指定历史会话）
  C 发出切换命令 → 解绑 C、绑定该任务会话 → persona 面呈现其对话流

阶段2 · 执行期（persona 面 = 当前任务会话的轮次流）
  loop 直到任务书全部任务终态：
  ├─ 轮次开始：C 经拟人执行端点输入测试消息 → persona 面 → 被测系统 → 任务会话回合执行
  ├─ 轮次产出回 persona 面（发起人实时可见）
  ├─ 轮次完成 → 任务会话内进入下一轮（任务内多轮 = 旅程连贯性来源）
  ├─ 任务完成 → 清场归档该任务会话 → 回阶段1 领下一个任务
  ├─ C 观察回路（静默·零 persona 面噪音）：机器读数读当前任务会话全量轮次
  │   逐轮判定通过/失败 + 取证 + 记台账
  ├─ 发起人插话 → 落入当前任务会话 = 新轮次（等价测试输入/干预）
  └─ 发起人切换命令 → 随时召回 C

阶段3 · 收权
  C 确认任务书全部任务终态 → 切换命令解绑任务会话、绑定 C

阶段4 · 终报
  C 独占 persona 面输出：总账/覆盖度量/缺陷/残余风险
  C 长回合收尾 = 全程唯一停止点
```

## 四、三通道纪律

- 指挥通道：发起人↔C，低噪音（仅里程碑/异常/待裁决时发声）
- 测试通道：当前任务会话↔被测系统，经拟人执行端点交互，测试面纯净
- 观察通道：C↔任务会话，纯机器读数（接口/日志/台账/取证），不过 persona 面

## 五、指挥官长回合守则

- 不停止：回合持续有动作即不衰减；唯一合法收尾=终报完成。
- 上下文防腐：观察回路低频化（分钟级），每轮只取增量摘要；重活全在 E，C 只做调度与判定。
- 待命纪律：无任务时不自发空转——待命=安静等待发起人消息，禁止巡逻式自唤醒（每次注入都是一次完整模型调用，叠加宿主负载）。
- 断点纪律：每个阶段切换与每批轮次完成时，将进度对账与下一步写入持久断点；长窗收判项用一次性时钟排程，不用常驻任务。

## 六、异常分支

| 异常 | 处置 |
|---|---|
| 任务会话某轮次挂起/僵尸无进展 | 观察回路的停滞检测：超过阈值判失→销账→通知发起人→清场重建该任务会话（只影响本任务，不堵其他任务）或跳过 |
| 任务会话上下文膨胀 | 默认不弃——任务内上下文是判据的一部分；确需重置→重置该任务会话上下文（绑定不变），断点文件带上下文摘要 |
| 绑定漂移（他端切换/选择错位） | 阶段切换前逐条对账目标标识；漂移后先复验再输入 |
| 经端点注入测试消息 | 发送前三件套缺一不发：①probe 确认客户端窗口在台 ②capture 确认当前绑定会话=目标测试会话 ③机器读数核在途——不复验就发可能把测试命令注入真实会话并 supersede 杀掉在途回合；有在途宁等或换新会话，不注入、不即兴中断 |
| 发起人想干预执行 | 插话落入当前任务会话；想改派/终止→切换命令召回 C |
| C 自身回合被异常打断 | 断点文件+持久台账支撑恢复；恢复后从断点继续，不从头重跑 |
| 执行会话中途死/失联 | 心跳文件（每回合写 `<报告树>/obs/heartbeat`：时间戳+契约哈希）+看门狗超阈值自动注入 `opencode run -s <会话> "按断点继续" --auto`——复活从「owner 发现」提前到「分钟级自动」（WO-20261113-1，实现层待工单） |
| 任务派单人肉化 | 任务队列文件+认领锁（审批卡认领制同款）：C 写单、E 认领、契约登记写者过户——机器接口闭环，零人参与成立（WO-20261113-2，实现层待工单） |

## 七、准入条件

- 拟人执行端点已过准入清单（五操作可用）
- 被测系统的会话绑定支持显式切换命令
- 机器读数通道可用（C 观察 E 的接口/日志/台账可达）
- 任务书已将全任务分解为任务清单（C 持书派单），每项任务标注会话策略（新建默认/复用连续性会话）

## 八、判定口径（双端对账）

- UI 主证 = 端点 capture()（判定当时回读，能发现错会话/错布局这类模板不可见异常）。
- 辅证 = 观察通道机器读数读服务端事实（会话消息/台账/待审列表/出站日志），与 persona 面展示逐格对照。
- 事件无 actor/原因字段时，不下行为归属结论——先设计判别实验（变量二分：杀进程/换环境/改时序，结局可二选一）再定性。
- 造数登记+清场：机器造数逐笔记台账，对象带可识别前缀；验毕即清，零残留。

## 九、被测系统运维协同与中断续跑

- 重启两法：常规=等空闲优雅重启（查在途台账，部署≠激活）；自杀矛盾=指挥者自身回合即唯一在途时，派分离后台进程执行重启——等待期即本回合落地窗口。复核两证：重启 armed 日志 + 审计日志分家（主动杀/验尸拉新）。
- 中断续跑：默认同载体回「继续」即续（会话由服务端持有，不丢上下文）；换载体场景写三行断点（任务=…/下一步=…/红线=…）至持久文件，单活（新盖旧）、完成即删；不预入队合成消息（伪造用户输入）。执行会话级心跳=每回合写 `<报告树>/obs/heartbeat`（时间戳+契约哈希），看门狗超阈值未刷新即自动注入续跑——回合中途死从「owner 发现」提前到「分钟级自动」（WO-20261113-1）。
- 深挖纪律：最小场景+判别实验（一次一变）；临时调试桩标「临时」，定位后移除或转正式观测；不可达如实记并附尝试证据，不为测试强造场景；审批类用例先核配置依赖（allow 覆盖会使 ask 永不触发）。
