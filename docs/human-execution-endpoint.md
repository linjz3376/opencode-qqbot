# 拟人执行端点（AEE）规范——通用可移植的拟人任务验证/执行指导思想

> 版本：1.0（2026-11-12 owner 当轮授权抽象定稿）
> 定位：一切「需要真人客户端配合」的验收/执行工作的宿主无关规程。135 机器=本规范的第一个适配器实例（win-native），不再是架构本身。
> 与 AGENTS.md §7.1 的关系：§7.1 收敛为 win-native 适配器的操作细则；本规范=其上层的抽象与跨端口语义。

## 一、核心抽象：AEE 是什么

AEE = 运行「被测 persona 真实客户端」的一台宿主（物理机/虚拟机/真机/浏览器/云真机），外加一个**五操作标准接口**的驱动层：

| 操作 | 语义 | 判定要求 |
|---|---|---|
| probe() | 宿主与客户端存活探测 | 返回 {宿主活、客户端进程/页面在、几何信息} |
| address(id) | 寻址到目标会话/页面 | 目标标识（标题/URL/群名）须在取证中可见——禁止假设上下文 |
| input(payload) | 拟人输入（文本/媒体/手势） | 等价真人输入事件；粘贴为下限，逐键为佳；输入后必有回执 |
| capture() | 判定时取证 | 从 persona 视角捕获（截图/DOM 快照）；判定时刻留证 |
| gesture(x) | 控件级动作（点/滑/滚动/对话框） | 动作后必须验证可观察变化，否则该次动作不算完成 |

**三通道纪律（任何 AEE 恒成立）**
- 指挥通道：owner↔指挥者，低噪音
- 测试通道：执行者经 AEE 与被测系统交互（测试面纯净）
- 观察通道：指挥者↔执行者，纯机器读数（REST/日志/台账），不过 persona 面

## 二、适配器档案（Implementation Profiles）

| 档案 | 宿主形态 | 遥控通道 | 输入原语 | 取证原语 | 实例 |
|---|---|---|---|---|---|
| win-native | Windows 桌面客户端（QQ/微信/Outlook 等） | WinRM→/it 计划任务链（交互会话交付） | keybd_event/mouse_event/剪贴板 | PrintWindow（绕 DWM 陈旧帧）/GDI | 135 机器（本项目现役） |
| web-dom | 浏览器内客户端 | Playwright/WebDriver | click/fill/keyboard 真实事件 | DOM 快照+判定时截图 | 浏览器类验收（技能默认通道） |
| android-adb | Android 真机/模拟器 | adb | `adb shell input` | uiautomator dump + screencap | 手机端用例（备用） |
| macos | macOS 客户端 | SSH/代理守护 | cliclick/AppleScript | screencapture | — |
| cloud-farm | 云真机平台 | 厂商 API | 厂商输入 API | 厂商截图 API | 设备农场场景 |

**适配器准入清单（每档上线前逐项实测打勾）**：真事件可用/判定时截图可用/对话框可处理/滚动可用/几何归位可用/凭据注入点隔离/单活或几何漂移有对策。**缺项=该端点降级声明，不得静默改判。**

## 三、可移植纪律（六纪律的宿主无关内核）

1. **身份锚定**：每阶段开头 address+取证确认目标标识可见；绑定漂移（任何端点都会发生）后不复验不发——对应 §7.1「发送前三件套」的抽象。
2. **几何纪律**：坐标永远从当前实测取证推导；布局变化全部作废重取；窗口几何先归位再操作（win-native 的 SetWindowPos 归位=本纪律的档案实现）。
3. **交互会话交付**：输入事件必须送达 persona 的真实交互会话——win-native 的「WinRM 落 session 0 被吞」教训抽象为：**遥控通道若落在非交互会话，一切输入静默失效，必须先经交互会话交付层**（/it 任务链/代理守护/平台 API 均可，按档案选型）。
4. **取证双模**：判读模式（agent 在环读图，能发现错会话/错布局这类模板不可见异常）为默认；陈旧帧/渲染挂起时按档案切换替代取证 API（PrintWindow 之于 GDI 即此类）。
5. **证据同时刻**：PASS 也留证；事后补证不升级判定。
6. **密钥隔离**：凭据只经密钥注入点进入驱动进程，不回显、不落盘、不入产物。

## 四、失效模式对照表（跨端口语义）

| 抽象失效模式 | win-native 实证 | 档案无关处置 |
|---|---|---|
| 输入静默丢失 | WinRM session 0 三杀 | 交互会话交付层前置（纪律3） |
| 取证陈旧/空白 | DWM 陈旧帧、QQ 消息窗挂起 | 替代取证 API+输入唤活+端点重启规程 |
| 绑定漂移 | owner 手机切会话/序号错位/超时回落 | address 复验+有意切换走显式命令 |
| 客户端只驻托盘 | QQ NT 重启托盘态 | 唤窗规程（二次启动/归位） |
| 凭据外泄风险 | cred 文件被误传 | 注入点单点+只读使用 |

## 五、与指挥官/执行者架构的接口

- AEE 是**执行者伸到真人世界的手**：执行者不绑 persona 面，一切 persona 交互经 AEE 五操作完成。
- 指挥官通过观察通道读执行者结果；AEE 的 capture() 产出即 UI 主证来源。
- 新端点接入=写一个适配器+过准入清单+在任务书造数通道表登记（可用性/授权两列），不改动上层架构。
