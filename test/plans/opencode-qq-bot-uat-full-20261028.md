**多角色、多账户原则**：本产品无管理员/普通用户分级，唯一准入机制 = `ALLOWED_USERS` 白名单（精确 openid，fail-closed）。本轮需 ≥3 个 QQ 身份：U-MAIN（白名单·私聊+群 member_openid 双配）、U-SECOND（白名单第二位，用于告警边界与数据隔离）、U-OUT（名单外，用于负向准入）。凭据只从环境密钥源取，不落文档。桌面端操作者身份用于 PERM 双端竞态（AC-PERM-011）与 G2 桌面旅程。

**跨块缝隙判据（换块接缝）**：① bot 重启（OPS→SESS/SLF）：会话映射、watch 订阅、mirror 开关、巡检状态全部延续；② 链路自愈（SLF→IM）：恢复后用户消息立即可答；③ 切会话（CMD→SESS）：切换后模型/Agent 设置重放生效；④ 审批决策（PERM→IM）：决策后 busy 解除、后续消息正常处理。

## 6. 执行者手册（任意 AI agent 拿到本文档即可执行）

### 你是谁
你是 §0 的 persona（QQ 用户 / 桌面双端用户 / 运维者 / 对账员）。全程以该用户心智操作：他想完成什么、在 QQ 窗口看到什么、怎样算成功/受阻。**遇到文档没写的情况，按「真实用户会怎么办」处理并记录**——你不是逐条打勾的机器人。

### 用什么操作
- 用户侧：QQ 客户端（桌面 NTQQ 或手机 QQ，人工操作或自动化均可），按实际聊天窗口收发消息；观察回显以窗口可见内容为准。
- 运维侧：PowerShell（进程/计划任务/文件操作）、`~/.openqq/` 运行时文件、bot 仓库目录（本机实例绝对路径不写死，执行环境以实际项目根为准，命令均以项目根为 cwd）。
- 桌面端：OpenCode 桌面版（第二端 persona 与审批双端竞态用）。
- 多身份隔离：U-MAIN/U-SECOND/U-OUT 用不同 QQ 账号，严禁混用；桌面端操作者与 QQ 用户分工明确。

### 执行规程
1. §2 环境自检 → GO/PARTIAL/NO-GO 判定并记录
2. 缺陷台账核对：本项目台账不存在（头部声明）→ 无 ⛔ 点；执行期新建 DEF 编号从 DEF-001 起
3. **按 G1→G2→G3→G-DOM-IM→G-DOM-CMD→G-DOM-SESS→G-DOM-PERM→G-DOM-OPS→G-DOM-SLF→G-DOM-AUD 场景执行**（需授权的 OPS/SLF 场景与操作者确认后再动；高风险负向点优先），场景内基本流→备选流→异常流；域顺序只做 AC 回归
4. 每场景完成挂靠 §3 验收点：QQ 回显判定 → 原文/截图取证 → 记录 ✅/❌/部分/⏭️/⏸️
5. 判定纪律：唯三可跳（⛔ 未修 / ⏭️ 无实现 / ⏸️ 口径挂起）；审批类点触发失败走 §2 条件分支（⏸️ 挂起，不裸判 BLOCKED）；禁止假装通过；「数据源验证」列只做辅证
6. 全部场景后按域做 AC 回归补漏；每 AC 终点写回场景日志
7. G0 自由探索 20 分钟，四栏笔记记录
8. 每场景一句场景级结论 → 七段式汇报 → 按 Final-Report-Gate 选择 final-report 或 interim-report

### 凭据
本文档零明文。QQ 测试身份、OpenCode base/password 一律从执行环境密钥源注入；缺失时仅阻塞依赖该身份的点，其余不受影响；禁止猜测或硬编码凭据。

### 用户知识与证据边界
以 QQ 窗口可见结果为判定主证；OpenCode REST、QQ REST、本地文件、日志、源码仅作辅证或本质不可由 QQ 观察项的取证，不替代用户侧结论。对 QQ 平台的一切发送均为真实发送（对象仅限测试身份）。

### 你不需要
不需要任何外部技能、记忆或培训；不需要访问本文档之外的任何版本化文件。

## 11. 汇报与缺陷格式

**七段式汇报**（每场景一草稿→汇总报告；**Final-Report-Gate：未触=0 方可出具 final-report.md，未触>0 一律 interim-report-<date>.md**）：①头部=任务 ID+环境 GO 判定+纪律声明+被测版本（git 短号）②场景级结论（11 场景逐句「作为 persona，能/不能完成业务目标」）③G0 皱眉时刻清单（分级）④验收点统计（✅/❌/部分/⏭️/⏸️ 分类计数，数字与 §3 的 88 点逐项对得上；未触 N 点明示）⑤缺陷清单（DEF 编号+粗粒度影响）⑥偏离与快照决策记录（授权清单执行记录/⏸️ 挂起理由）⑦结论=总体判定（未触=0 时可用「收官 GO/带伤 GO」，否则窗口口径）+必改项+MEASURES（含 AC-AUD-001 对账差集处置）。

**十段式缺陷**（每个 ❌ 一条，用户语言）：①编号 DEF-xxx ②标题（用户视角，如「我发的图超过 10MB 后机器人完全不提图的事」）③严重级别+场景 ④复现步骤（QQ 入口+消息原文）⑤预期 ⑥实际（含用户侧证据路径）⑦证据（截图/消息原文；内部取证标「辅证」）⑧初判根因（可缺省标「待研」）⑨评分依据 ⑩登记号与复验口径。

**产物树**（随报告交付，目录按本项目实际用 `test/` 适配）：
```
test/reports/<date>/
├── final-report.md 或 interim-report-<date>.md   # 七段式（Final-Report-Gate 见 §5）
├── defects/DEF-*.md                              # 十段式缺陷各一条
├── evidence/<AC-ID>/                             # QQ 回显截图/原文、日志辅证
├── cleanup-list.md                               # 清场清单（含 .env 原值恢复记录）
├── coverage-table.md                             # 深度维度覆盖表终态 + C01–C32 对账终态
└── g0-notes.md                                   # G0 四栏笔记与皱眉时刻
```
